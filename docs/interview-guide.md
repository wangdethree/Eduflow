# 面试说明

## 一分钟项目介绍

EduFlow 是一个基于 FastAPI 和 Vue 3 的智慧学习平台，支持学员、教师和管理员三类角色，完成课程创建审核、学习进度、在线考试、消息通知和教学统计闭环。后端使用 SQLAlchemy 2.0/MySQL 持久化，Redis Lua 处理高频进度，Celery 做批量落库和考试提醒，MinIO 负责预签名直传。项目重点不是普通 CRUD，而是 JWT 双令牌轮换、RBAC 加数据权限、课程状态机、考试幂等和可测试的容器化交付。

## 最值得讲的设计

### 为什么先做模块化单体

业务规模和团队规模尚不需要微服务。模块化单体能在一个事务中维护课程、答卷、错题和通知的一致性，部署与本地调试成本低。通过领域目录和 Service/Repository 边界保留未来拆分可能；当团队、独立扩缩容或故障隔离需求真实出现时，再按考试、文件、通知等边界拆分。

### 学习进度为什么用 Redis Lua

视频播放器可能数秒一次上报，如果每次写数据库会产生大量更新和锁竞争。Lua 在 Redis 内原子读取并合并：旧时间戳不覆盖新数据、播放位置不倒退、学习时长累加，随后 Celery 批量落库。风险是最终一致和 Redis 故障，因此开启 AOF、缩短落库周期、读取时优先缓存，并用唯一约束和 compare-delete 防止并发丢数据。

### 考试如何防重复提交

第一层用 Redis `SET NX EX` 限制同一用户同一考试的并发提交；第二层在数据库对 `(exam_id, user_id)`、`idempotency_key` 和 `(attempt_id, question_id)` 设置唯一约束；第三层业务发现答卷已评分时直接返回原结果。Redis 锁提升体验和降低冲突，数据库约束才是最终正确性边界。

### JWT 如何安全退出

Access Token 无状态且短期有效；Refresh Token 在数据库中只存哈希和 JTI。刷新时撤销旧 Token 并签发新 Token，检测到旧 Token 重放时不能继续建立会话。退出撤销 Refresh Token，修改密码增加用户 `token_version` 并撤销会话，使旧 Access Token 失效。生产环境还应使用 HTTPS、Secure/HttpOnly Cookie 策略和密钥轮换。

### 权限为什么不只做 RBAC

`course:update` 只能说明教师拥有编辑课程这一类操作权限，不能说明他可以编辑任何教师的课程。Service 继续校验 `course.teacher_id == current_user.id`。接口权限与数据归属同时存在，才能防止横向越权。

### 文件为什么预签名直传

大文件经过 FastAPI 中转会占用应用带宽、连接和内存。预签名 URL 让客户端直接上传 MinIO，应用只负责授权和元数据。上传完成回调还会校验对象是否存在、大小和声明是否一致，私有文件下载使用短期签名。

## 诚实说明的边界

第一版没有支付、直播、实时聊天、微服务、Kubernetes、推荐算法和大模型问答。当前消息是站内信加定时任务，没有 WebSocket；统计以实时 SQL 聚合为主，没有离线数仓；可观测性是结构化请求日志和健康检查，没有完整指标/链路追踪。这些是范围控制，不应包装成已实现能力。

## 常见追问

### Redis 挂了会怎样？

进度上报和考试锁会受影响，普通数据库读取仍可工作。生产上应做健康检查、超时、降级与告警；考试正确性仍由数据库唯一约束保护。进度若要求零丢失，可增加客户端本地队列或消息日志，再由后台消费。

### Celery 任务重复执行会怎样？

进度落库使用唯一键 upsert，提醒使用唯一 `source_key`，因此可重复执行。任务成功后 compare-delete 只删除仍等于已处理值的缓存，避免误删处理中产生的新进度。

### 为什么不用同步 SQLAlchemy？

FastAPI 的外部 I/O、Redis、数据库与对象存储调用都适合异步；异步可提高高并发等待场景的连接利用率。但异步不会让 CPU 计算变快，也提高了调试复杂度，所以自动评分保持轻量，重任务放到 Celery。

### 统计量大后怎么演进？

先补索引和查询计划，再用按天聚合表和异步增量更新；数据量继续增长时将事件进入消息队列，写入 OLAP 或数仓。教师实时概览与平台历史报表可以采用不同一致性与时效目标。
